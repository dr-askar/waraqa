# Architecture and development map

Waraqa is a static website/PWA plus a small Android WebView wrapper. The official
wrapper loads `https://dr-askar.github.io/waraqa/`; a fork must explicitly review
its origin allowlist, hosting, application ID and signing identity.

| Area | Location | Responsibility |
| --- | --- | --- |
| Domain | `src/domain/` | Typed document operations |
| Application | `src/application/` | Use-case orchestration |
| Infrastructure | `src/infrastructure/` | Adapter to existing local document store |
| Presentation | `src/presentation/` | React/TypeScript workspace |
| Existing web features | `dist/*.js` | Scanner, OCR, editors, export, encrypted storage and Drive |
| Generated workspace | `dist/workspace/` | Rebuilt by `scripts/workspace-build.mjs` |
| Third-party engines | `dist/vendor/` | Generated by build; not checked in |
| Native integration | `android/app/src/main/` | Share inbox, safe WebView bridge, exports and notification shortcuts |
| Verification | `checks/`, `.github/workflows/pages.yml` | Logic, browser and Android emulator checks |

`dist` contains both maintained source files and generated bundles. Edit the `.js`
feature source or `src/` as appropriate, not generated workspace bundles. This is an
incremental architecture, not a completed migration of every legacy module.

Documents and originals stay in local IndexedDB. Optional password locking encrypts
document records. Native incoming files are temporary until import/cancel. Drive
authorization and sync are optional and need owner OAuth setup. Backups include
originals; a redacted export is not equivalent to a redacted backup.

New features should have an explicit operation, an adapter and a presentation step;
avoid placing database writes in UI components. Reread revisions before saves,
preserve cancel/undo behavior and test encrypted/offline paths. See
[editing rules](EDITING-AND-RECOVERY.md) for actual recovery limits.

## Roadmap, not promises

1. Community onboarding, license notices and reproducible store preparation; see [community settings](COMMUNITY.md).
2. Real-device accessibility, RTL/LTR and memory/performance reviews.
3. Better modular boundaries for legacy image/OCR workflows.
4. More local OCR samples and translations with measurable results.

Prioritize issues with reproducible evidence. Specialized handwriting, automatic
book dewarping and cloud AI are not implied by this roadmap.
